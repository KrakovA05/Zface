# Analytics Insights Design

**Goal:** Добавить раздел «Паттерны» в AnalyticsScreen — до 3 автоматически вычисленных инсайтов на основе реальных данных пользователя. Только математика, без AI.

**Architecture:** Новый утилит `computeInsights.js` принимает данные и возвращает массив строк. AnalyticsScreen загружает дополнительные данные (mood 28 дней, счётчик сообщений по неделям) и передаёт их в утилит. Раздел Premium-гейтирован.

**Tech Stack:** React Native, Supabase (дополнительные запросы в существующем `load()`), нет новых пакетов.

## Паттерны и математика

### Паттерн 1: Тренд измерения за месяц
**Данные:** `user_metrics` — все записи, упорядоченные по `week_start ASC`  
**Логика:**
- Нужно минимум 8 записей
- `recentAvg` = среднее по последним 4 неделям для каждого измерения
- `prevAvg` = среднее по неделям 5–8 от конца
- `delta = recentAvg - prevAvg`
- Если `delta ≤ -8`: «[Измерение] снизилась на X пунктов за последний месяц — динамика положительная.»
- Если `delta ≥ 10`: «[Измерение] выросла на X пунктов за последний месяц — стоит обратить внимание.»
- Показываем только самую большую abs(delta) из 8 измерений

### Паттерн 2: Чат-активность и одиночество
**Данные:** счётчик сообщений по неделям из `messages` + `user_metrics.loneliness_score`  
**Запрос:**
```sql
SELECT date_trunc('week', created_at) AS week, COUNT(*) AS cnt
FROM messages
WHERE sender_id = $userId
GROUP BY week
ORDER BY week DESC
LIMIT 8
```
**Логика:**
- Нужно минимум 4 пары (неделя с активностью + loneliness_score той же недели)
- Делим недели на «высокая активность» (выше медианы) и «низкая»
- `highLone` = avg loneliness в высокоактивные недели
- `lowLone` = avg loneliness в малоактивные недели
- Если `lowLone - highLone ≥ 8`: «В недели когда ты больше общаешься, одиночество ниже — разница X пунктов.»

### Паттерн 3: Настроение в выходные vs будни
**Данные:** `mood_checkins` за последние 28 дней (расширить с 7 до 28)  
**Логика:**
- Нужно минимум 5 будних + 2 выходных чекина
- `wdAvg` = среднее по пн–пт, `weAvg` = среднее по сб–вс
- `diff = weAvg - wdAvg`
- Если `diff ≥ 1.5`: «В выходные настроение обычно выше — в среднем на X балла.»
- Если `diff ≤ -1.5`: «В выходные настроение ниже, чем в будни.»

### Паттерн 4: Общий прогресс с начала
**Данные:** `user_metrics` — первая и последняя запись  
**Логика:**
- Нужно минимум 4 записи
- `delta = last.composite_score - first.composite_score`
- Если `delta ≤ -10`: «С начала использования общий индекс снизился на X — это положительная динамика.»
- Если `delta ≥ 10`: «Общий индекс вырос на X с начала использования.»

---

## Правила отображения

- Показываем **максимум 3 инсайта** — отбираем по убыванию abs(delta)
- Каждый инсайт содержит **конкретное число**: не «снизилась», а «снизилась на 14»
- Если данных недостаточно (< 4 недель): заглушка «Появятся через несколько недель использования»
- Если данные есть, но ни один паттерн не достиг порога: заглушка «Паттернов пока не обнаружено — продолжай пользоваться»

## Premium-гейт

Раздел «Паттерны» виден только `store.isPremium === true`.  
Для бесплатных пользователей: карточка с замком, заблюренный текст-заглушка с примером инсайта, кнопка «Разблокировать в Premium».

## Интерфейс computeInsights

```js
// Вход
computeInsights({
  metricsHistory,   // [{week_start, composite_score, anxiety_score, ...}] — ASC
  moodHistory28,    // [{checkin_date, score}] — последние 28 дней
  messageCounts,    // [{week, cnt}] — последние 8 недель DESC
})

// Выход
// string[] — 0–3 инсайта, готовые к отображению
```

---

## Ограничения

- Не делаем корреляцию Пирсона — достаточно сравнения средних
- Не показываем инсайты с delta < порога, чтобы не создавать ложную значимость
- Текст инсайтов фиксированный (не AI) — нет риска галлюцинаций
- Раздел не появляется на экране пока `isPremium === false`
